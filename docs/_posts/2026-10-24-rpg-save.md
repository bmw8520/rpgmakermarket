# RPG Maker Save Files: Locations, Formats and Editing

![Hand-drawn save-file motifs frame title area](https://media.babylovegrowth.ai/blog-images/organization-61610/1792827720762_Hand-drawn-save-file-motifs-frame-title-area.jpeg)

An RPG Maker save is a numbered file in the game's save folder. MV writes `.rpgsave` files, MZ writes `.rmmzsave` files, and both hold your party, items, switches and variables as compressed data. You can find them, back them up and edit them. You can also change how your own game saves. Which of those you need depends on whether you are a player stuck on a bad save or a developer building the save system.

This guide is written mostly for developers and tinkerers working with RPG Maker MV and MZ. It covers what is inside a save, where it lives, how to edit one without breaking it, and how to change save behavior in your own project.

## TL;DR

- MV saves are numbered `.rpgsave` files, and MZ saves are numbered `.rmmzsave` files. Both hold compressed JSON, so a plain text editor will not do for MZ or for most MV games.
- Look first in a `save` folder inside the game folder. Some builds use Windows AppData, and browser-packaged builds can keep saves in browser storage instead of files.
- Before editing anything: close the game, copy the original, edit the copy and keep the exact filename.
- Both MV and MZ give players 20 save slots by default, and MZ has built-in autosave. Plugins can change the slot count, the screen layout and the storage path.

## What is inside an RPG Maker save file

A save file is a snapshot of the game state at the moment you pressed Save. RPG Maker's own documentation describes the Save command as [recording the current game state](https://rpgmakerofficial.com/product/MZ_help-en/01_06.html), and MV's feature notes add that [the game title is stored in the save file](https://rpgmakerofficial.com/product/MV_Help/page/01_01_01_08.html).

Inside, you will find the things that make your run yours. According to a [guide on editing RPG Maker saves](https://savegame.org/guides/how-to-edit-an-rpg-maker-save/), a decoded MV save holds party gold, actor levels and stats, item quantities, switches and variables. Another guide breaks the decoded structure down into [system data, party and gold, actors, map state, switches and variables](https://saveeditor.top/blog/how-to-edit-rpg-maker-save/).

Switches and variables matter most. They are how the editor tracks story progress: whether a door is unlocked, whether you spoke to the blacksmith, how many times you lost a fight. Change a gold value and you get a richer party. Change the wrong switch and a quest can no longer finish.

### Save file types by engine version

The extension tells you which engine made the game and how the data is packed.

| Engine | Extension | Format |
|---|---|---|
| RPG Maker MZ | `.rmmzsave` | zlib-compressed JSON |
| RPG Maker MV | `.rpgsave` | LZ-string-compressed JSON |
| RPG Maker XP | `.rxdata` | Ruby Marshal binary |
| RPG Maker VX | `.rvdata` | Ruby Marshal binary |
| RPG Maker VX Ace | `.rvdata2` | Ruby Marshal binary |

The MV, MZ and older-engine details come from the same [save-editing guide](https://savegame.org/guides/how-to-edit-an-rpg-maker-save/). One caveat on MV: some games compress the save with LZ-string and some do not, and the files that are not compressed can be opened directly in a text editor according to the tool docs that circulate with the community editors. Do not count on that. Check the first few characters of the file before you decide how to open it. Readable JSON that starts with a curly brace is uncompressed. A block of unreadable characters is compressed.

The older XP, VX and VX Ace formats are binary, so none of the JSON advice below applies to them.

## Where RPG Maker save files are stored

There is no single answer, and that is what makes this question so common. The location depends on the engine version, how the game was packaged and whether a plugin changed the storage path.

### The usual places to look

1. **The game folder.** MV and MZ saves are commonly in a `save/` subfolder in the game folder, and XP, VX and VX Ace use a `Save/` folder there, [per the same guide](https://savegame.org/guides/how-to-edit-an-rpg-maker-save/). For a deployed MV game, that often means `www/save` next to the game data.
2. **Windows AppData.** Some MV and MZ builds write to AppData instead of the game folder. If the game folder has no save directory, search your user profile for the game's title.
3. **macOS app bundles.** A forum explanation notes that on macOS, packaged apps place save data [under the application bundle's Resources area](https://forums.rpgmakerweb.com/threads/rpg-maker-saving-locations.117626/). Right-click the app and show package contents.
4. **Browser storage.** Browser-packaged builds may keep saves in [browser local storage rather than ordinary files](https://saveeditor.online/rpg-maker-save-editor). There is no file to find. Clearing site data in your browser can erase your progress, so export or back up first if the game offers it.

The same forum thread points out that plugins can override the default path. So if you have checked every normal location and found nothing, the game probably uses a custom storage setup. The location is decided by the deployment platform and the storage configuration, not simply by the editor version.

### The other files in the save folder

Open a save folder and you will see more than your numbered saves. A forum breakdown of how saves work explains that [the global file tracks save-slot metadata, the config file stores options, and `.bak` files are backups](https://forums.rpgmakerweb.com/threads/how-saves-work-in-rpgm-games.152544/) made during the write process. Leave these alone unless you are troubleshooting. If a game shows empty slots when files exist, the global file is the first suspect.

## How to edit an RPG Maker save safely

Most people editing saves want one of three things: more gold, a fix for a broken switch, or a look at the data for debugging. The method is the same for all three.

1. **Close the game.** An open game can overwrite your edit when it next saves.
2. **Copy the original save** to a safe place. This is your undo button.
3. **Edit the copy**, not the original, with a tool that understands the format.
4. **Keep the exact filename.** The game looks for numbered files, so a renamed file will not appear in the load screen.
5. **Put the edited file back** in the save folder and load it.

The backup, copy and filename steps follow the [savegame.org walkthrough](https://savegame.org/guides/how-to-edit-an-rpg-maker-save/), which also says editors can change currency, levels, stats, inventory, switches, variables and story-driving event state.

### Why a generic text editor is not enough

It is tempting to decompress the file, paste it into any JSON tool and save. That is where saves get broken. A [guide to MV and MZ save editing](https://savefileeditors.com/rpg-maker-save-editor) explains that both engines use RPG Maker's JsonEx serialization with different compression, so a general JSON tool is not enough for reliable editing.

The same guide notes that MV preserves object and reference metadata such as `@c`, `@r` and `@a`, while MZ uses a simpler representation. If you rebuild the JSON carelessly, you can break object identity or methods, and the game may crash on load or behave oddly. The practical rule: change values in place and never restructure the data.

### Edit small, test often

Change one value, load the save, confirm it worked, then change the next. If something breaks, you know which edit caused it. For story switches, write down the original value first. A switch you flipped for testing can quietly skip a cutscene that sets up something later.

## Are online save editors safe?

They can be, but you should check how each one handles your file. A save is small and rarely contains personal data, yet it is still your file, and some games embed a player name or a title.

There are two kinds of tool. A local one processes the save in your browser, so the file never leaves your device. The savegame.org guide [claims exactly that](https://savegame.org/guides/how-to-edit-an-rpg-maker-save/) for its editor. An upload tool sends the file to a server. One online editor page describes a workflow in which [uploaded saves can be searched and edited in the browser](https://saveeditor.online/rpg-maker-save-editor), and that wording alone does not tell you whether processing stays local.

To check for yourself:

- Open your browser's developer tools, go to the Network tab, load a save and watch for outgoing requests that carry the file.
- Disconnect from the internet after the page loads. A truly local editor still works.
- Always keep your backup, whatever the tool says about privacy.

## Save slots and autosave: what the engine gives you

If you are building a game, start with what ships in the box. RPG Maker MZ's official guide says the Save command [offers 20 save slots](https://rpgmakerofficial.com/product/MZ_help-en/01_06.html), and MV's help [documents 20 as well](https://rpgmakerofficial.com/product/MV_Help/page/01_06.html). MV's feature notes add that the maximum [increased from 16 to 20](https://rpgmakerofficial.com/product/MV_Help/page/01_01_01_08.html) in that version.

MZ also treats autosave as built-in. The [official MZ product page](https://store.rpgmakerofficial.com/products/rpg-maker-mz) lists autosave and separate autosave slots as configurable in the editor. Players reach saving through two doors: the in-game Save command and the Continue command on the title screen.

### Changing the number of slots

Twenty is plenty for a short game and too few for a sprawling one where players like to keep a save before each choice. Community threads on the topic describe the fix as a small script in your plugins folder with the slot count changed. Test any change on a fresh project first, because the count also affects the layout of the save screen.

### Redesigning the save and load screen

The default list is functional, not pretty. MV's official help documents an [AltSaveScreen plugin](https://rpgmakerofficial.com/product/MV_Help/page/01_11_10.html) that changes the layout of the save and load screen and can show party face images. That is a good first step if you want players to recognize their slots at a glance.

### What actually gets written

For deeper changes, look at how the engine builds the data. The MV library documentation says [`DataManager.makeSaveContents` creates the object written at save time](https://kinoar.github.io/rmmv-doc-web/classes/datamanager.html), while `DataManager.extractSaveContents` restores that object into the game's variables. If your plugin keeps its own data, such as a minigame high score or a custom quest log, add it to the contents object on the way out and read it back on the way in. Give your keys a unique prefix so two plugins never collide.

## Our perspective: treat the save as part of your design

We have spent years building plugins for MV and MZ, and the most common support question is not about features. It is about a save that stopped working after a plugin was added or removed. That is worth understanding, because it shapes how we build.

A plugin that stores its own data in the save creates a dependency. Remove the plugin mid-project and old saves may no longer match what the game expects. So we tell developers to decide early which plugins are staying, test loading an old save after every change, and keep each plugin's data small and clearly named. Modularity helps here: adding one capability at a time makes it obvious which change broke a file.

![Our perspective: treat the save as part of your design — overview diagram](https://media.babylovegrowth.ai/blog-images/organization-61610/1792827837625_Our-perspective-treat-the-save-as-part-of-your-design-overview-diagram.jpeg)

For players and modders, our advice is simpler. Back up first, edit a copy, change one thing at a time. Most corrupted saves we hear about come from someone restructuring data instead of changing a value.

And if your game ships with minigames or a custom travel system, playtest saving in the middle of them. Players will save at the worst possible moment, and a good game survives it.

## Troubleshooting common save problems

**The save folder does not exist.** The game may not have saved yet. Create a save in game, then look again. If it is still missing, check AppData and browser storage.

**The edited save does not show up.** Check the filename and extension first. The file must match the numbered pattern the game expects and sit in the folder the game actually reads.

**The game crashes when loading an edited save.** Restore your backup. The usual cause is changed structure, a value of the wrong type, or a missing object reference. Redo the edit changing only a number.

**Saves vanished after an update.** Deploying a new build can change the storage location, and a browser build can lose local storage when site data is cleared. Check where the new build writes before assuming the files are gone.

**Old saves break after adding a plugin.** Plugins that change the save contents can make older files incompatible. Test with a copy of an old save before you ship an update to players.

## FAQ

### What is an RPGSAVE file?

It is the save format of RPG Maker MV. The file stores your game progress, such as character status, inventory and quest data, as [described by a file-extension reference](https://filext.com/file-extension/RPGSAVE). In practice it is compressed JSON, so you need a compatible tool to read it.

### Where is the RPG Maker save file located?

Most often in a `save` folder inside the game folder, and for deployed MV games often `www/save`. Some builds use Windows AppData, macOS packaged apps keep data inside the app bundle, and browser builds use local storage. If none of those hold your files, a plugin may have moved the path.

### Is RPG Maker MZ or MV better?

It depends on what you need. For saving, MZ adds built-in autosave with separate slots, which MV handles through plugins, while both offer 20 slots by default. Choose the engine your plugins and team already support, since each uses a different save extension and format.

### Can I increase the number of save slots?

Yes. The default is 20 in both MV and MZ, and a small plugin script can change it. Test on a copy of your project, because the save screen layout depends on the count.
